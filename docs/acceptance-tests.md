## 1. 進め方

- リリースの前に、全項目を実施する。
- 「OS」列：W＝Windows 11、L＝Linux（検証用 PC：EndeavourOS ＋ KDE Plasma、Wayland セッション）、W/L＝両方。

### 1.1 テストデータ

| 名前 | 内容 |
|---|---|
| `sample.ts` | 30 秒程度の MPEG-TS（映像＋音声）。ファイル名に日本語と空白を含むコピー `テスト 動画.ts` も用意する |
| `audio_only.wav` | 映像のないファイル |
| `broken.ts` | 途中で切れたファイル（ffmpeg がエラーになる） |
| `long_path\…\sample.ts` | フルパスが 260 文字を超える場所に置いたコピー（W） |
| `Transcoding_sjis.ini` | 本家の書き方の `Transcoding.ini`（Shift-JIS、`[0Item]` と `[*テンプ or ゴミ]` を含む。中身は同梱のプリセット例がもと。`crates/sc-core/tests/fixtures/ini/transcoding_sjis.ini`） |
| `Transcoding_utf8.ini` / `Transcoding_utf8bom.ini` | 同じ内容を UTF-8（BOM なし / あり）にしたもの |
| `probe.ini` | 置換変数をファイルに書き出すだけのテスト用プリセット（[本家動作調査記録](original-behavior.md) の方法） |
| `fail.ini` | 2 番目のコマンドが必ず失敗するプリセット（`cmd /c exit 1` / `sh -c "exit 1"`） |
| `slow.ini` | 1 つのコマンドが 60 秒以上かかるプリセット（中断の確認用） |
